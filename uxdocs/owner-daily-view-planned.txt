  contract, and the unit split are all defined in the specification above.
  These wireframes show intent and information hierarchy. Where a wireframe and

Still true

  admin-operational-views-ux-proposal.md is still a proposal, not shipped.

Decided 2026-08-19 (spec 12.1 — do not relitigate)
  Window is ROLLING 24h/48h back from now. Not Florida business days. No third
  mode. Reasoning: this is an operational view, not a reporting view — a
  business-day board is nearly empty at 8:00 AM and files the overnight call
  leads under yesterday. Comparable day-over-day numbers stay in /analytics.

  /daily is ITS OWN PAGE. / remains HomeOverview (analytics overview + quick
  links), unchanged. Daily View is a new sidebar item above Form Leads. No
  other admin's landing experience changes.

  Cancellation Intakes wait for Granot Unit 26. The Daily View does not wait
  for it — ODV-G ships the Booking half plus a not_built panel.

Route
  /daily?tab=<tab>&window=24h|48h&open=<kind>:<id>
  Owner-only. Added to OWNER_ONLY_PAGE_PREFIXES.

      Booking Intakes ②    open intakes

      ⚠ Reconnecting…          last poll failed, retrying
      ○ Live off               owner switched it off
  A board that silently stops updating is worse than one that never claimed to.

 12. BUILD ORDER (mirrors spec section 9)
================================================================================

  A   window contract + capabilities + Overview tab            <- first value
  B   Leads / Bookings / Cancellations tabs + drawer + chain
  C   live feed poll + useDailyFeed() + live indicator
  D   LeadConversation model + redactor + read routes + ONE seeded record
  E   Conversations tab + drawer conversation panel + audio URL
  F   Agents tab
  G   Booking Intakes tab (gated) + Cancel Intakes (needs Unit 26)
  H   DEFERRED — automated conversation pipeline. Gated on cost, retention,
      PCI, and consent. Do not merge back in early: the moment a discovery
      cron exists, those decisions have been made by default instead of by the
      Owner.
  I   optional — SSE transport swap behind useDailyFeed(), only if 3s polling
      proves insufficient.

  Realtime, short version: producers are separate Vercel lambdas, so there is
  no shared memory and an in-process EventEmitter CANNOT work in production
  even though it will appear to work in `next dev`. Ship the 3s cursor poll.
  See spec section 4.
