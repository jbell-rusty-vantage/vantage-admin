1) GRANOT LIFECYCLE  (Ingestion → Granot → Lifecycle)
State: LIVE queue/detail (owner). Command forms exist; Booking commands stay gated off until the server flag is enabled.
================================================================================

What it does
  Owner queue for Granot Booking Reconciliation Cases. Review Granot evidence
  separately from official Vantage Booking / Cancellation facts, browse eligible
  Lead candidates, and resolve an open standard Booking case with an explicit
  command. Distinct from Granot Automation and from Booking Lead Reconciliation.

Where
  /ingestion/granot/lifecycle
  /ingestion/granot/lifecycle/cases/[caseId]
  /ingestion/granot/lifecycle/jobs/[jobNo]
  Tabs: Automation vs Lifecycle (owner). Not in the main sidebar as its own item;
  open Ingestion → Granot workflow → Lifecycle.

How to use
  1. Open Ingestion → Granot → Lifecycle (owner only).
  2. Filter the open queue (kind, mode, source, job, dates). Open a case.
  3. Read Granot evidence as evidence only. Official fields are never copied
     from Granot estimate/payment values.
  4. Resolve when commands are offered:
       Confirm Granot Booking   — create-missing: pick an eligible Lead
                                  (Suggested Booking Lead is a suggestion only)
                                  and enter official Book Date, Agent
                                  Allocations, Binder, Deposit, Merchant.
       Update Existing Booking  — review-existing: full replacement starts from
                                  the live Booking projection (active catalog
                                  IDs), never Granot evidence.
       No Action                — close the case without changing a Lead,
                                  Booking, or Cancellation.
  5. Job timeline is available from the job route. A Booking that still needs
     a Lead may link out to Booking Lead Reconciliation.

Important
  Command buttons appear only when the server advertises `commands`. Checked-in
  Booking-command flag stays false. Booking vs Release kinds stay separate.
  Capability flags must not advertise future Release or discrepancy command UIs.
  Referral create mode has no command form here. Polling refreshes evidence;
  unsent drafts are kept. A 409 refreshes facts and keeps your entries — submit
  again explicitly.

2) GRANOT CRM AUTOMATION  (Ingestion → Granot → Automation)
State: LIVE
================================================================================

What it does
  Builds a durable plan of CRM updates for Form Leads and/or Call Leads across
  selected source companies for a date window, then waits for your approval
  before writing. After approval it walks each selected source company.

How to use
  1. Open Ingestion → Granot → Automation (owner only).
  2. Lead types: check Form Leads, Call Leads, or both.
  3. Source companies: pick which sources to include for each selected lead type
     (Best Relocation sources stay unchecked by default until you opt in).
  4. Set From and To dates.
  5. Choose Preview only, or Preview then allow approved updates.
  6. Create plan(s). Selecting both lead types creates two plans in one group.
  7. Open a run awaiting approval. Review actions, confirm the plan checksum,
     approve the selected actions.

Important
  Approve and finish one lead-type plan before starting the other. Each approved
  plan still processes through every selected source company for that lead type.

3) BEST RELOCATION INGESTION  (Ingestion → Best Relocation)
State: DISABLED (schedule / env gate off). Source wiring is up to date.
================================================================================

What it does
  Pulls Best Relocation leads and bookings into Vantage. Once enabled, a cron
  schedule ingests from 2026-04-30 through current time on the configured cadence
  (24h or 48h).

How to use (when ready to turn on)
  1. Open Ingestion → Best Relocation.
  2. Inspect sources to confirm health.
  3. If bootstrap is still required: Plan bootstrap → review → Approve exact plan.
  4. After bootstrap is complete and the deployment gate is enabled: Enable schedule.
  5. Optional: Preview now for a one-off plan; approve when status is awaiting approval.
  6. Watch run history and resolve any conflicts shown on the page.

Do not enable until you intentionally want live Best Relocation ingestion.

4) REPORTING  (/reporting)
State: LIVE. Google Picker API is being fixed (destination folder/sheet picking).
================================================================================

What it does
  Create custom Google Sheet report definitions with any time-frame slice
  (explicit date range or rolling “last N days”). You can scope reports to
  specific source companies / granularities if you want company-level sheets.

How to use
  1. Open Reporting.
  2. Create a definition: pick dataset, name it, set timezone and date window,
     choose columns, optionally filter to source companies, pick a destination.
  3. Preview the draft. Fix any blocking warnings.
  4. Save / revise the definition.
  5. Prepare a run → review destination impact → Confirm to write the sheet.

Destinations
  Manage under Reporting → Destinations. Google Picker for choosing folders /
  spreadsheets is currently being fixed; destinations already registered still work.

5) OPERATIONS REGISTRY  (/operations-registry)  ** IMPORTANT **
State: LIVE (owner mutations; others read-only)
================================================================================

What it does
  Central catalog for the business graph. Create and manage Agents, Merchants,
  Lead Source Companies (and channel granularities), reviewed Granot CRM
  sources, RingCentral inbound queue numbers, and granular CPL costs. Everything
  is interconnected: changes propagate into bookings, ingestion recognition,
  filters, analytics, and reporting source selection.

How to use (tabs)
  Overview        — counts and health findings.
  Agents          — create/activate agents so they can be selected on bookings.
  Merchants       — create/activate merchants so they can be selected on bookings.
  Sources         — create Lead Source Companies + form/call granularities so
                    ingestion from a site is recognized and attributable.
  Granot sources  — owner review/update/activation of exact Granot CRM labels,
                    lifecycle disposition, link_only/observation_only policy,
                    route dependencies, and automation compatibility.
                    create_if_missing is a later rollout and cannot be selected.
                    Non-owner admin role is read-only.
  RingCentral     — create a draft inbound queue number → Validate → activate /
                    start ingesting once validated.
  CPL             — set cost-per-lead rates granularly (by source/channel slots);
                    updates backfill matching leads for analytics.
  Changes         — audited registry change history.

Rule of thumb: add the registry entity first, then expect dropdowns, ingestion
recognition, and reports to pick it up across the rest of the dashboard.
