## Rendering rules honoured (server handoff)

Null counts read "Pending" (never 0); `cadence_disabled` / `cadence_shadow` / `policy_unavailable` metrics read "Unavailable" with the reason; the M1 goal label is the server's count-scope label with "Other outbound" kept separate; the browser never computes overdue or order (statuses, flags and order are the server's; only relative times and "overdue by" durations are interpolated from `as_of`); `job_pending` rows show "Job number pending" with Copy disabled; 403/404 clear the selected lead and its cached rows; 409 `CURSOR_EXPIRED` reloads page one; every write sends the server revision and an Idempotency-Key.

## Decisions taken without stopping (also in LEDGER)

- My view opens on **New leads** (reference) with All leads as a third tab; Team defaults to All leads.
- Move date defaults to **Any move date** (the spec's "Upcoming" is marked proposed; any date hides nothing and needs no excluded-count chip by default).
- Callback scheduling is collapsed behind "Schedule a callback" until used, keeping the panel like the reference.
- First load selects the first queue row (reference); after a revocation or a close nothing is auto-selected.
- Lead age = New York calendar days since received (Day 1 = arrival day), because queue rows carry no `schedule_day` (contract request 2); the panel shows the server's schedule day.
- Manager Settings = attendance only; Activity is composed from queue + detail reads (contract request 3).
